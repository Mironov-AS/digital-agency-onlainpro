Техническое задание на продукт для продуктовой полки: Электронная запись. 
1. Назначение сервиса
Сервис предназначен для автоматизации процесса записи клиентов на приём к специалистам компании клиента. Позволяет администраторам клиента вести каталог услуг, записывать посетителей, а сотрудникам клиента— отслеживать загруженность по дашборду календарю.
2. Целевая аудитория
•	Администраторы клиента — создают и редактируют услуги, записывают клиентов, вносят данные.
•	Сотрудники фирмы — просматривают загруженность через дашборд.
•	Посетители — косвенно участвуют как объекты записи.
3. Основные функции
1.	Ведение каталога услуг:
o	добавление новых услуг;
o	редактирование существующих услуг;
o	удаление услуг (с проверкой наличия записей);
o	просмотр списка услуг.
2.	Запись посетителей на приём:
o	выбор даты и времени приёма;
o	ввод номера автомобиля клиента;
o	указание контактного телефона клиента;
o	выбор услуги из каталога;
o	поле для комментариев (свободный ввод).
3.	Дашборд календарь:
o	отображение записей в календарном виде (день/неделя/месяц);
o	цветовая индикация по услугам или статусам;
o	фильтрация по услугам, сотрудникам, датам;
o	детализация при клике на запись (все введённые данные);
o	генерация постоянной ссылки на дашборд;
o	режим отображения для табло (упрощённый вид, крупные элементы).
4. Функциональные требования
4.1. Модуль каталога услуг
•	Интерфейс списка услуг с возможностью:
o	сортировки по названию, длительности, цене;
o	поиска по названию услуги.
•	Форма добавления/редактирования услуги с полями:
o	название услуги (обязательное, до 100 символов);
o	описание (опционально, до 500 символов);
o	длительность (в минутах, целое число);
o	стоимость (число с двумя знаками после запятой);
o	статус (активна/архив).
4.2. Модуль записи клиентов
•	Форма записи с полями:
o	дата приёма (календарь с выделением доступных дат);
o	время приёма (выбор из интервалов с шагом 15 минут);
o	номер автомобиля (строка, 7–12 символов, валидация формата);
o	телефон клиента (формат +7 XXX XXX XX XX, валидация);
o	услуга (выпадающий список из активного каталога);
o	комментарий (многострочное поле, до 1 000 символов).
•	Проверка на пересечение записей (не допускать наложения по времени для одного специалиста).
•	Сохранение записи с присвоением уникального ID.
4.3. Модуль дашборда
•	Календарь с тремя режимами отображения:
o	день (почасовой график);
o	неделя (сетка дней с временными слотами);
o	месяц (обзор загруженности по дням).
•	Визуализация записей:
o	цвет по типу услуги;
o	всплывающая подсказка при наведении (все данные записи);
o	индикатор статуса (подтверждена/ожидает/отменена).
•	Фильтры:
o	по услугам (чекбоксы);
o	по специалистам (если их несколько);
o	по датам (диапазон).
•	Режим «для табло»:
o	увеличенный шрифт;
o	крупные блоки записей;
o	автообновление каждые 30 секунд;
o	отсутствие элементов управления (только просмотр).
4.4. Общие требования
•	Аутентификация администраторов должна быть такой же как для продукта электронная очередь. 
•	Журналирование действий (кто, когда, что изменил).
•	Адаптивный интерфейс и UI как в проекте Цифровое агентство.

5. Нефункциональные требования
•	Производительность: загрузка дашборда — не более 3 секунд при 1 000 записей.
•	Надёжность: доступность 99,9 % времени, восстановление после сбоя — не более 15 минут.
•	Безопасность: HTTPS, хеширование паролей, защита от SQL инъекций и XSS.
•	Масштабируемость: поддержка до 10 000 активных записей одновременно.
•	Локализация: интерфейс на русском языке.
6. Требования к интерфейсу
•	Интуитивная навигация (не более 3 кликов до любой функции).
•	Единообразие элементов управления.
•	Подсказки для полей ввода.
•	Визуальная обратная связь при действиях (сообщения об успехе/ошибке).
7. Требования к интеграции
•	Возможность экспорта записей в CSV/Excel.
8. Критерии приёмки
•	Успешное прохождение юнит тестов (90 % покрытия).
•	Подтверждение работоспособности на тестовой базе с 500 записями.
•	Положительное тестирование UX сценариев (запись клиента, просмотр дашборда).
•	Соответствие требованиям безопасности (аудит).
